---

## Course Overview

Data structures provide systematic ways to organize, store, access, and process information.

This course introduces fundamental data structures and their associated algorithms through the integration of:

* discrete mathematics
* data representation
* C++ programming
* algorithm design
* complexity analysis
* programming practice
* automated testing
* responsible AI-assisted learning

The course emphasizes not only how a data structure is implemented, but also why it is designed in a particular way, which algorithms operate on it, and how its correctness and efficiency can be evaluated.

The overall learning sequence is:

> **Discrete Mathematics → Data Representation → Algorithms → C++ Implementation → Practice and Evaluation**

## Course Description

This course introduces fundamental data structures and algorithms for undergraduate students.

Topics include:

* arrays
* linked lists
* stacks
* queues
* trees
* binary search trees
* heaps and priority queues
* graphs
* hashing and hash tables
* searching and sorting
* selected advanced data structures
* integrated applications

For each topic, students will examine the underlying mathematical concepts, investigate how the structure can be represented in memory, study the algorithms that operate on the structure, and implement the corresponding data structures and algorithms in C or C++.

Programming assignments will focus on implementing required data structures together with fundamental algorithms. Selected assignments will use GitHub Actions and instructor-provided test cases to evaluate compilation, correctness, and selected boundary conditions.

---

## Learning Outcomes

Upon successful completion of this course, students should be able to:

1. Explain the concepts and properties of fundamental data structures.
2. Describe the mathematical foundations associated with common data structures.
3. Represent abstract relationships using appropriate data structures.
4. Implement fundamental data structures and operations in C or C++.
5. Apply basic algorithms to manipulate and process structured data.
6. Analyze the time and space complexity of algorithms.
7. Compare alternative data structures and implementations.
8. Select appropriate data structures for computational problems.
9. Design test cases for normal, boundary, and exceptional conditions.
10. Use Git and GitHub to maintain programming work and learning progress.
11. Interpret automated testing results and revise implementations.
12. Use AI tools responsibly when permitted.
13. Explain and defend the design and correctness of submitted programs.

## Learning Approach

Each topic will be studied from several connected perspectives.

| Perspective                 | Guiding Question                                                           |
| --------------------------- | -------------------------------------------------------------------------- |
| **Discrete Mathematics**    | What mathematical concepts, relations, or properties define the structure? |
| **Data Representation**     | How can the data and their relationships be represented in memory?         |
| **Algorithms**              | What operations and algorithms can be applied to the structure?            |
| **C++ Programming**         | How can the structure and algorithms be implemented correctly?             |
| **Complexity Analysis**     | What are the time and space requirements?                                  |
| **Practice and Evaluation** | How can correctness and performance be evaluated using test cases?         |
| **AI-Assisted Learning**    | How can AI support explanation, debugging, and verification responsibly?   |

The intended learning process is:

> **Understand → Represent → Design → Implement → Analyze → Test → Reflect**

## Programming Assignment Workflow

Programming assignments should generally follow this process:

1. Read the complete assignment specification.
2. Identify the required data structure and operations.
3. Understand the required input, output, and program interface.
4. Design the internal data representation.
5. Implement the required data structure.
6. Implement the associated algorithm.
7. Compile and test the program locally.
8. Test normal, boundary, and exceptional cases.
9. Commit meaningful development stages using Git.
10. Push the implementation to GitHub.
11. Review GitHub Actions results, when provided.
12. Identify and correct failed test cases.
13. Verify the final submission.
14. Complete the required documentation.

A program should not be considered complete merely because it compiles.

A complete submission should:

* satisfy the required interface
* produce correct results
* handle specified boundary cases
* use the intended data structure
* apply the required algorithm
* contain understandable source code
* include sufficient documentation
* preserve meaningful development history

On-site attendance is required.

* lecture content
* in-class activities
* quizzes

Students who cannot attend class for a valid reason should inform the instructor as early as possible.

### Academic Integrity

All submitted work must reflect the student's own understanding and effort.

The following are prohibited:

* plagiarism
* unauthorized copying
* submitting another person's work
* falsifying programming or learning records
* submitting code that the student cannot explain

Late submissions will be subject to grade deduction.

The detailed deduction policy may vary by assignment and will be stated in the corresponding assignment instructions.

Technical problems caused by missing backups, incomplete uploads, incorrect repository settings, or failure to verify the final submission are normally not considered valid reasons for an exception.

### Accountability

Students are expected to demonstrate:

* **Progress:** Stay on track and seek help before problems accumulate.
* **Ownership:** Understand and take responsibility for submitted work.
* **Technical responsibility:** Maintain backups and verify submissions.
* **Communication:** Report valid issues promptly and clearly.
* **Collaboration:** Contribute fairly and distinguish collaboration from copying.
